## 一、现状诊断（基于 2026-07-31 版本）

### 优势
1. **AI/Agent 落地证据强**：月均 Token 2133 亿、单月 2.9 万篇英文文档、成本降 80% 等数字有冲击力。
2. **角色清晰**：项目负责人 + 架构 + 工程实现，不是纯写文档。
3. **跨界背景稀缺**：翻译学 + 技术内容 + Agent 工程，差异化明显。

### 主要问题（HR / 招聘方视角）
1. **求职目标未写清**：不知道你要冲「AI 应用工程师 / Agent 平台 / 知识工程负责人 / 技术内容 Leader」哪一类。
2. **经历时间线错位**：核心项目写在工作经历之前，且 2020–2025「高级技术文档工程师」几乎只有三条 bullet，贡献被压扁。
3. **岗位叙事偏「做了什么」**：技术栈堆叠多（模型名、SDK、工具），对「你解决了什么业务问题、你个人不可替代点」不够锋利。
4. **管理与协作深度不足**：带 6 人、跨产品线推进有，但缺规模、方式、结果（人效、质量、周期）。
5. **技能区缺失**：没有独立技能矩阵（Agent / 工程 / 内容 / 语言 / 管理）。
6. **联系方式冗余**：手机号重复出现在电话与邮箱位；可补充 GitHub / 作品集（若有）。
7. **近期空白风险**：项目写到 2026.03，当前已是 2026.07——需补 4–7 月在做什么，否则像「停更」。

## 二、目标简历结构（新版草案）

1. **页眉**：姓名 · 目标岗位 · 城市 · 电话 · 邮箱 ·（可选）链接  
2. **一句话定位 + 3 行摘要**（按目标岗位定制）  
3. **核心竞争力**（4–6 条关键词，非证书堆砌）  
4. **工作经历**（时间倒序；每段 3–6 条「场景 → 动作 → 结果」）  
5. **代表项目**（1–2 个深挖，其余折叠进经历）  
6. **技能清单**  
7. **教育 / 证书**（精简）

原则：一页优先（中文技术岗可 1.5 页）；数字可核验；模型版本名适度，避免简历变成工具清单。

## 三、信息采集轮次（资深 HR 访谈）

| 轮次 | 主题 | 产出 |

| R4 | 早期经历补强 | 淘宝 + 阿里云文档阶段管理、产品、影响力 |
| R5 | 技能 / 作品 / 风险点 | 技术栈真实度、开源/作品集、离职原因、竞业等 |
| R6 | 定稿偏好 | 中英版本、篇幅、风格、敏感数据脱敏 |

每轮结束后：答案写入 `docs/interview-notes/` → 更新 `resumes/draft/` 草稿 → 再进入下一轮。
